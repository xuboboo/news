## 二、修复明细

### 1. 事件聚类正确性（P0）

- **并入已有事件统一三段式门槛**：`event_service.run_event_clustering` 并入分支改用与簇内合并完全相同的 `similarity_gate_pass`（带级相似度 + 关键词 + 跨来源），另加事件区间与簇区间的时间窗相邻校验；关键词口径统一 `keyword_jaccard_of`（预计算免分词）；多个过门候选取 sim 最高。
- **成员重叠救援分支加语义下限**：保留幂等守卫用途，但目标事件 max 成员相似度必须 ≥ sim_threshold，按 (重叠数, sim) 取最优；零门槛认领（混题事件放大器）废除。
- **高位带不再零条件直通**：新规则 = 跨来源佐证 + 关键词重合 ≥ `HIGH_BAND_KW_FLOOR`（默认 0.1，管理面板可热调）；同来源高位相似（Win11 学院形态）一律不并。
- **真实数据校准**（177 篇 / 3000 随机负例对）：正例同事件对 14/14 全部通过新门槛（最低 kw=0.11）；负例仅 1 对边缘通过（99.97% 精度）。旧行为下负例有 237 对可直通。
- **发现并修复预置 bug**：`SessionLocal` 为 `autoflush=False`，新建事件的成员关联在当轮质心重算与二阶段合并查询中不可见（质心滞后一轮、重复事件多活一个周期）；已在新增关联后显式 `flush()`。
- **cosine/centroid 维度断言**：维度不一致抛 `EmbeddingError`（含双方维度指纹），废除 zip 静默截断。

### 2. 认证与会话（P1）

- 租户迁移先保存旧租户再比较，迁移后旧会话即时吊销；审计 detail 记录 `tenant_id=旧→新`。

### 3. 采集部分失败可观测（P1）

- `TaskRun.status` 新增 `degraded`；crawler 双入口（celery task + 常驻 loop）检查 `per_source.error` 置 degraded。
- 告警巡检新增规则：同一任务连续 3 轮 degraded → webhook 告警；偶发降级只进面板。
- 管理面板任务记录新增黄色「降级」徽章。

### 4. 日报口径（P1）

- `articles_count`/`sources_count` 改为日报窗口内统计；全生命周期数字移入 `lifecycle_articles_count`/`lifecycle_sources_count`；概览文案自动使用窗口口径。

### 5. API 契约（P2）

- `/articles/latest`：`id DESC` 稳定二级排序；搜索改标题 OR 标签（与前端一致）。
- `/hot/board`：新增 `window=24h|3d|7d|all` 参数；归一化基准改窗口内全频道最大分（切频道分数稳定）；`publish_time, id` 稳定二级排序。

### 6. 前端数据链路（P1/P2）

- **热榜接服务端**：页面改调 `/hot/board?window=&channel=`，删除客户端过滤/排序/归一化，榜单口径单一化。
- **直用 eventIds**：`mapApiArticle` 保留 `event_ids`，`eventsForArticle` 优先后端全量关联（缓存反推降级为兜底）。
- **ai_status 三态**：有摘要 → 摘要；pending → 「AI 摘要处理中…」；其余 → 「暂无 AI 摘要」，失败任务不再永远"生成中"。
- **日报**：选中日期写入 URL（分享/刷新不丢）；日期 chips 展示全部期数（废除 14 期截断）；"较上期"缺失自动补拉；复制失败红色提示。
- **最新资讯**："加载更早的资讯" offset 分页（增量刷新保留页尾文章）；"实时时间轴/实时同步"改"定时同步"并展示最近同步时刻。
- **状态与安全**：ErrorBoundary 生产环境只展示稳定错误编号（FNV-1a 哈希），不暴露内部 message；"内置演示数据"过时横幅改为真实的断线文案。
- **前端测试**：引入 vitest，9 个用例覆盖 client 映射/事件关联/三态文案/加载更多去重（此前零测试）。

### 7. 发布硬化（审计"发布前"项）

- `ENVIRONMENT=production` 启动 fail-fast：cookie_secure / enable_docs / admin_no_auth / 默认 DB 口令任一不合规拒绝启动（`.env.example` 检查单同步）。
- nginx CSP **Report-Only**（只观察不拦截，观察后收紧）；`high_band_kw_floor` 纳入管理面板热调白名单。
- **502 坑代码化**：nginx `resolver 127.0.0.11 valid=30s` + 变量式 proxy_pass，backend 重建换 IP 不再需要连带重启 nginx。

## 五、复核轮结论（2026-09-10 第二次逐项核对）

双代理对四份报告全部条目做第二轮代码级核对：后端 10 组项全部确认落地（仅 task_run 状态注释漏 degraded，已补）；前端 10 项中确认 9 项，**发现 2 处首轮遗漏并已补齐**：

1. **头部状态条引导期闪烁**（审计 4.3 明确项）：`SyncStatus` 原先只判 `apiMode`，引导进行中会先闪"后端未连接 · 自动重连中"。已补 `useBootstrapReady` 分支——引导期显示中性"正在连接后端…"，确认离线后才出琥珀色告警条（侧边栏与主横幅首轮已修，本轮补齐头部后三处语义一致）。
2. **事件列表 limit=100 内存快照**（审计 4.2"固定 400/100 快照"的事件侧）：文章/热榜/日报首轮已改服务端分页，事件页仍消费 bootstrap 的 100 个事件缓存。已补 `loadMoreEvents`（offset 分页，`/events` 本就支持 offset/total）+ Events 页"加载更早的事件"按钮 + 增量刷新保留页尾事件（与文章同模式），关联反查缓存随之补全。
3. **测试缺口补齐**：日报期号递增与同日幂等集成测试（计划内有、首轮漏写）已加入 `test_integration_pg.py`（同日重复生成同行同期号、次日 +1、跳日 +N），容器内 6 个 pg 集成用例全绿。
