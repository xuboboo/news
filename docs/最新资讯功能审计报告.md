# 最新资讯功能审计报告

> 审计日期：2026-09-09  
> 审计范围：最新资讯页面、相关 API、AI 摘要、事件聚合、前端交互和运行状态  
> 审计方式：代码审查、后端测试、前端构建/lint、本地运行环境验证、登录态只读 UI 验收  
> 审计结论：**66/100，暂不建议按当前事件聚合结果直接上线**

## 一、结论摘要

最新资讯的基础链路基本可用：文章采集、列表展示、频道筛选、关键词搜索、详情弹窗、AI 摘要、标签和自动刷新均能正常工作。

但登录后的真实 UI 验收发现，资讯卡片上的“关联热点事件”存在严重误聚类。大量完全无关的文章被关联到同一个热点事件，且数据库中存在“单一来源、几十篇互不相关文章”的事件簇。这会直接影响最新资讯、热点事件页和软件日报的可信度，是当前最高优先级问题。

静态审计初评为 78 分；在登录态验收中发现事件数据正确性问题后，将最终评分下调为 **66 分**。

## 三、缺陷清单

### P1：热点事件严重误聚类，影响资讯可信度

这是当前最严重的问题。

页面中大量完全无关的文章被关联到同一个事件：

> 六人利用 AI“越狱”生成淫秽物品最终获刑，法官提醒“技术中立≠技术无罪”

实际观察到被错误关联的文章包括：

- A16z 风投观点
- NOVA2.0 具身智能
- 美国国防部与 OpenAI
- OpenAI CFO 芯片设计
- 京东物流机器人
- Meta Muse
- AI 教育、AI 电力需求等

数据库进一步确认：该事件当前包含 23 篇文章，但全部来自单一来源，且标题主题明显互不相关。

相关代码：

- [`backend/app/ai/event_cluster.py`](../backend/app/ai/event_cluster.py#L61)
- [`frontend/src/api/client.ts`](../frontend/src/api/client.ts#L74)

根因判断：

1. 当前 `sim_threshold=0.85`。
2. 当相似度达到 `0.89`（阈值加 `HIGH_BAND=0.04`）后直接合并。
3. 高相似度分支绕过了关键词重合和跨来源校验。
4. 随机负样本中也存在高相似度文章，因此“高相似度直接合并”并不安全。
5. 前端没有直接使用后端返回的 `event_ids`，而是通过缓存事件反向推导文章关联，进一步放大了关联不完整和错配风险。

影响：

- 最新资讯卡片展示错误热点。
- 文章详情展示错误“关联热点事件”。
- 热点事件页和日报可能继续继承错误聚类。
- 用户会误以为不同新闻属于同一事件。

严重级别：**P1，数据正确性和产品信任问题**。

### P1：最新列表固定只加载 400 篇

前端固定请求：

```text
/articles/latest?limit=400
```

后端虽然支持 `offset`、`limit` 和 `total`，但前端没有分页、加载更多或历史范围切换。

相关代码：

- [`frontend/src/api/client.ts`](../frontend/src/api/client.ts#L220)
- [`backend/app/api/v2/routes.py`](../backend/app/api/v2/routes.py#L221)

当前数据量尚未超过 400 篇，因此暂时不明显；数据持续增长后，旧资讯会直接从页面消失，用户也不知道还有更多数据。

### P2：前后端搜索语义不一致

界面提示为“搜索标题或标签”，前端支持标签搜索，但后端 `q` 参数只搜索标题。

相关代码：

- [`frontend/src/pages/Latest.tsx`](../frontend/src/pages/Latest.tsx#L46)
- [`backend/app/api/v2/routes.py`](../backend/app/api/v2/routes.py#L232)

当前前端主要依赖本地已加载数据，因此短期可用；一旦改成分页或服务端搜索，会出现搜索结果不一致。

### P2：相同发布时间缺少稳定排序

后端目前仅按 `publish_time DESC` 排序：

```python
order_by(Article.publish_time.desc())
```

同一发布时间的文章顺序可能在刷新后变化。建议增加 `id DESC` 作为第二排序键。

### P2：AI 状态没有充分区分

后端返回了 `ai_status`，但前端没有完整使用。摘要生成失败、处理中、没有摘要等状态容易统一显示为“AI 摘要生成中”。

建议明确区分：

- 处理中
- 已完成
- 失败，可重试
- 未生成

### P2：实时性描述略有夸大

页面显示“实时同步中”，实际情况是：

- 爬虫约 15 分钟执行一次
- 前端约 60 秒刷新一次

更准确的描述应是“定时同步”，或同时展示最近一次同步时间。

### P2：降级文案与当前实现不一致

[`frontend/src/components/Layout.tsx`](../frontend/src/components/Layout.tsx) 中仍有“当前展示的是内置演示数据”的提示，但当前客户端实现已经不是纯演示数据模式，容易造成误解。

## 五、建议修复顺序

1. **立即暂停或隐藏低置信度事件关联**，避免继续向用户展示错误热点。
2. 修复事件聚类规则，取消高相似度直接合并，增加关键词、实体、时间窗口、来源和主题一致性校验。
3. 对现有 `event`、`event_article` 数据重新聚类，当前数据不建议直接保留。
4. 前端改为使用后端 `event_ids`，避免通过缓存反向推导事件关系。
5. 增加分页或加载更多能力。
6. 增加事件聚类回归测试，至少覆盖本次发现的 A16z、NOVA2.0、京东物流等错误样本。
7. 补充摘要失败、排序稳定性、搜索口径一致性的测试。
