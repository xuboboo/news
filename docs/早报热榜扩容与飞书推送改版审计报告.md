## 三、审计发现

### P1（需用户处理）：早报推送配置已丢失，明早 08:00 将不会推送

- 现状三处皆无配置：`system_setting` 表无 `report_push_*` 覆盖行（仅剩 `embedding_fingerprint`）、运行容器无相关环境变量、`.env` 中推送配置全部处于注释状态。
- 但 2026-09-18 22:55:29 存在 `admin.test_report_push → wecom:ok` 的成功记录，证明当时配置生效；此后至今**无任何** `config_updated` / `config_reset` 审计记录。
- 审计哈希链校验通过（无删改），排除「API 层改配置且抹除痕迹」的可能；配置行消失路径应为**绕过 API 的直接数据库操作**（审计体系按设计只覆盖 API 路径）。
- **处置**：在「运维监控」页重新配置飞书机器人（总开关 + webhook URL + 可选签名密钥），并点「测试推送」验证（该操作有审计留痕）。

### P2（遗留代码，低风险）：`render_report_markdown` 的飞书 footer 分支成为死代码

- 飞书通道改走 `render_feishu_text` 后，markdown 渲染器内 `if provider == "feishu"` 分支不再被生产路径触达（仅存量测试覆盖）。
- **建议**：下轮清理时删除该分支与对应测试，收敛渲染器职责（只服务企微）。

### P3（已知边界，可接受）：历史快照的补位去重依赖新字段

- `featured_article_ids` 仅存在于 2026-09-19 之后生成的快照；旧快照走「测试推送」时，热榜补位不剔除事件成员文章，同一资讯可能以「事件标题 + 成员文章标题」出现两遍（前端按数组实际长度渲染旧快照 5 条热榜，无兼容问题）。
- 影响面：仅旧期数的补位场景（事件+速览不足 8 条时），自然消化、无需迁移。

### P4（上游改进建议）：本地抽取式摘要以原文导语开头

- 未配置 LLM 时 `summary_short` 为原文首句截断，速览说明依赖本侧剥壳清洗兜底；个别形态（如「微软于当地时间 9 月 18 日…」的状语变体）仍无法完美剥离。
- **建议**：摘要服务侧对导语句做源头处理，或接入 LLM 摘要后此问题自然消解。
