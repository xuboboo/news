# 网站资讯稿：独立编辑板块

## 用途和流程

`/site-drafts` 与现有 `/drafts`（公众号草稿）分开。资讯弹窗或事件详情选择“生成网站稿”；生成后编辑 CMS 对应字段、逐项复制，人工上传标题图片、审校事实，最终在网站后台手动提交。这里的“就绪”只表示可编辑，**不是已经发布**；系统不会登录、提交或改造你截图里的 CMS。

两个板块共享用户每小时生成次数限制、AI 总开关、模型和成本看板。网站稿 AI 用量单独标成 `site_article`，公众号稿仍为 `article`。跨租户全员共享草稿是系统现有政策：有登录权限的成员可以查看、编辑、删除两类草稿；请勿在里面放保密内容。旧草稿在数据库里默认 `wechat`，不会混入网站稿列表，也不会自动迁移。

### 截图字段映射

| 网站后台字段 | 网站稿板块 | 处理方式 |
| --- | --- | --- |
| 标题（必填） | 标题、备选标题 | AI 起草；人工核对事实后逐项复制。保存上限 80 字，是工具约束，不是搜索引擎排名门槛。 |
| 页面关键字 | 页面关键字 | 固定 3 个相关短语（品牌词、品牌加版本词、问题型长尾），英文逗号分隔；非 Google 排名因素。 |
| 标签 | 标签 | AI 给出栏目建议，人工复核，避免大量同义标签。 |
| 发布时间 | 拟定发布时间（北京时间） | 默认留空，由人工按实际发布时刻填写；不得用 AI 猜测事件发生时间冒充发布时间。 |
| 置顶、推荐、头条 | 三个复选框 | 默认均关闭，只由编辑决定；不会由 AI 设置。 |
| 标题图片（截图要求 1:1 方图） | 标题图片构图建议 | AI 只提供文字建议，没有文件或上传接口；必须由人工使用有授权的图片到网站后台上传。 |
| 关联软件 ID | 整数输入 | 默认 0；只有人工确认了对应软件后才填入真实 ID，AI 生成始终强制 0。 |
| 内容简介（必填） | 内容简介 | AI 给出独立、准确的文章摘要（目标 60~100 字，核心词前半句）；是否作为 HTML `meta description` 输出取决于目标网站模板。 |
| 长尾承接选题 | 长尾承接建议（只读+复制） | AI 从素材拆出 5~8 个可独立成篇的长尾选题（疑问词+意图强度+内容形式+建议标题），用于“快讯层+服务层”两层内容策略；发布本文后逐篇另写并互相内链。 |
| 新闻正文（必填） | Markdown 编辑/预览、“复制新闻正文” | 剪贴板含格式化 HTML 和纯文本；**正文不含任何参考来源**（2026-10-11 起，按编辑要求彻底移除），**不重复复制主标题**，因为 CMS 有独立标题字段。人工粘贴后要核对编辑器清洗格式。该工具不在正文中附加 AI 生成声明；公开发布前请按适用规定另行确认内容标识要求。 |

### SEO 原则与边界

- 标题具体、简洁、与正文一致，避免夸张、复写相同关键词。Google 标题显示没有固定字符数限制，可能根据设备截断或改写；[百度搜索网页标题规范](https://ziyuan.baidu.com/college/articleinfo?id=2728)同样要求准确、简明、避免堆砌。
- 内容简介描述当前页面而非套模板；Google 搜索摘要主要从页面正文产生，也可能采用 `meta description`，不保证展示本字段。
- Google 不将 `meta keywords` 作为索引或排名信号；截图的“页面关键字”仍可为该 CMS 或其他用途填写，不能宣称会提高 Google 排名。
- 可信的来源、实际报道事实、人工审校比追求固定字数或机械堆词重要。网站版与公众号版提示词分开，不因 SEO 凭空增加功能、价格、数据或软件关联。
- **网站稿生成不是单轮改写**：系统先建立编辑简报（搜索意图、读者问题、事实账本、来源差异、文章角度和不可声称内容），再进入写作阶段；事件聚类摘要只作线索，报道正文才是事实依据。
- **文章类型按题材切换**：版本更新、产品发布、系统预警、事故进展、单源更新和一般事件使用不同的写作重点；单一来源不会被包装成多方报道。
- **原创价值有边界**：系统要求做来源之间的对照、变化解释、限制条件和受影响人群说明，但没有实测、采访或独立数据时不会伪造第一手原创。
- **质量门会拦截低质稿**：自动检查空泛小标题、文章流程套话、重复段落、来源单篇高相似、标题/简介重复、关键词形态、单源过度声称和信息量过薄；发现硬问题会带着具体反馈重写一次，仍不通过则标记失败，避免把低质稿交给编辑。
- **SEO/GEO 不是关键词堆砌**：标题和内容简介围绕真实搜索问题生成，页面关键字只是 CMS 辅助字段。Google 官方强调页面应提供原创信息、分析或实质增值，避免规模化低价值改写；Bing 的生成式搜索可见性同样依赖可验证、清晰、可引用的页面内容。
- 真正的 `NewsArticle` 结构化数据、日期、可索引图片、规范网址与 sitemap 应由**正式网站模板**提供，而不是粘贴到 CMS 正文；编辑稿无法保证搜索收录、排名或富结果。

参考：Google Search Central 的 [标题链接建议](https://developers.google.com/search/docs/appearance/title-link)、[搜索摘要建议](https://developers.google.com/search/docs/appearance/snippet)、[meta 标签（明确忽略 meta keywords）](https://developers.google.com/search/docs/crawling-indexing/special-tags)、[以读者为先的内容](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)、[文章结构化数据](https://developers.google.com/search/docs/appearance/structured-data/article)。

## 模型响应超时

网站稿的两阶段请求使用独立读取等待：编辑简报 300 秒，正文写作及质量重写 600 秒；连接和连接池等待均为 20 秒，发送请求等待为 30 秒。它们是 HTTP 各阶段的等待限制，不是整篇草稿的总耗时保证。公众号、摘要和事件总结保留原来的超时设置，Celery 的 1 小时硬时限不变。

简报要求最多 12 条不重复事实、4 个读者问题、6 个大纲小节，不输出思考或长篇成稿；输出 token 上限为研究 8192、写作 12288，其中思考型模型的思考 token 也会占用供应商的输出额度。不能仅按最终可见正文的字数设置上限。

网络超时不会自动重试，因为服务端可能仍在处理已经发送的请求；超时流水没有供应商返回的用量，0 token 只代表未收到用量，不能视为供应商不收费。报错会说明所处阶段及等待限制。请稍后使用草稿详情页的“重新生成”手动重试；生成失败不会覆盖已有正文。JSON 格式修复仍最多一次，质量重写仍最多一次；每次请求分别记录耗时和用量，草稿 token 合计包含已知的格式失败尝试。

2026-10-11 排查记录：QQ PC 端“迷你窗”草稿（11）研究请求耗时约 110 秒，写作请求在旧的 180 秒读取限制处超时，整篇约 291 秒。通过模拟研究 110 秒、写作 190 秒的离线回归验证了新阈值，并验证了读取/连接/发送超时分类、无自动重试及失败保留正文；没有用该故障记录自动再次调用供应商。修复后后端 485 项通过、25 项依环境跳过；本机后端与任务容器已重建更新，9 个服务均健康，健康接口返回 200。

2026-10-11 提示词升级：网站稿两阶段提示词重写（研究阶段新增实体与硬信息锚点 `entities`/`quotable_details`，写作阶段新增反合理化清单、句式节奏与标题/关键词/标签的具体规范）；质量门最低字数上调为快讯 300/深度 480，新增来源编号与来源尾注泄漏硬错误；生成时自动清除模型自写的“参考来源：…”尾注行。同日线上实测发现 GLM 思考 token 计入 max_tokens 会吃满输出预算导致 JSON 截断，`llm_client` 新增 `thinking` 参数，网站稿两阶段显式关闭思考（实测同题 A/B：关闭后 token 降约 96%、耗时降约 95%，质量门得分持平）。写作阶段改为 **best-of-2**：每次生成两个独立候选（temperature 0.45/0.6），全部合格则按“阻断→警告→标题字数→信息量”自动择优；两候选都不过闸才带着较优者的问题清单定向重写一次。超时/接口失败仍立即失败不重试；每次生成固定为 3 次模型调用（1 研究+2 写作）。完整分析、依据与预期效果见 `docs/网站资讯稿提示词优化方案.md`。同日晚间按编辑要求再调整：**网站稿正文彻底移除参考来源**（后端不再追加“## 参考来源”脚注、复制时也不再重建；来源快照仍留库供审计），页面关键字由 3~6 个改为**恰好 3 个**（品牌词、品牌加版本词、问题型长尾）。后端全量 492 项通过、25 项按环境跳过；前端 103 项通过。

## 历史草稿清理

当前版本的提示词、生成落库、人工保存、预览和复制均不再附加 AI 生成声明，参考来源仍保留。旧稿详情也会过滤历史自动声明；以下脚本可显式清理数据库中的旧声明，无需调用模型或重生成正文：

```bash
docker compose exec -T backend python scripts/remove_draft_ai_disclosures.py          # 只预览
docker compose exec -T backend python scripts/remove_draft_ai_disclosures.py --apply  # 确认备份后写入
```

脚本仅处理网站和公众号草稿，保留原正文及参考来源，跳过正在生成或仍由生成任务持锁的草稿，每篇修改增加修订版本，重复执行不会再次改动。迁移后请刷新已经打开的草稿页面，避免使用旧修订版本保存。

2026-10-11 本机验收：清理 2 篇网站稿、3 篇公众号稿，包括正文中无 Markdown 标题的旧声明；通过还原被删行后的内容哈希，确认正文与来源没有其他改动。后端 464 项通过、25 项因环境条件跳过；前端 103 项通过，构建与静态检查通过；已更新前后端和相关任务容器，9 个服务均健康。清理只涉及草稿库，不会修改已人工发布到外部 CMS 的内容。

## 技术边界与验证

网站稿通过 `channel=site` 与旧 `wechat` 草稿隔离：独立路由、读写 API、生成提示词、任务和审计动作，复用表的版本锁及材料快照。启动时为旧库幂等补列并建板块索引，旧行默认公众号。队列恢复按 `channel` 选择对应任务；两个板块共用成本额度锁以避免并发超限。编辑、重生成、删除均携带修订版本防覆盖。

验收记录：本次编辑简报/质量门改造后，后端离线 469 项通过、25 项按环境跳过；前端 103 项通过，构建与静态检查通过。此前本机已清理 2 篇网站稿、3 篇公众号稿的旧声明，并通过内容哈希确认正文与来源没有其他改动。当前网站稿生成会分为研究与写作阶段，使用 `site_article` 流水分别记录调用，质量门失败会保留失败原因而不交付低质正文。没有调用真实供应商模型，没有自动向网站发布，也没有直接处理目标 CMS 的登录或图片上传。

网站稿任务只消费隔离测试中假模型或正式配置的模型；无素材会失败而不调用模型。本板块目前没有 CMS 自动发布/图片上传或真实搜索引擎收录测试。
