# 网站资讯稿：独立编辑板块

## 用途和流程

`/site-drafts` 与现有 `/drafts`（公众号草稿）分开。资讯弹窗或事件详情选择“生成网站稿”；生成后编辑 CMS 对应字段、逐项复制，人工上传标题图片、审校事实，最终在网站后台手动提交。这里的“就绪”只表示可编辑，**不是已经发布**；系统不会登录、提交或改造你截图里的 CMS。

两个板块共享用户每小时生成次数限制、AI 总开关、模型和成本看板。网站稿 AI 用量单独标成 `site_article`，公众号稿仍为 `article`。跨租户全员共享草稿是系统现有政策：有登录权限的成员可以查看、编辑、删除两类草稿；请勿在里面放保密内容。旧草稿在数据库里默认 `wechat`，不会混入网站稿列表，也不会自动迁移。

### 截图字段映射

| 网站后台字段 | 网站稿板块 | 处理方式 |
| --- | --- | --- |
| 标题（必填） | 标题、备选标题 | AI 起草；人工核对事实后逐项复制。保存上限 80 字，是工具约束，不是搜索引擎排名门槛。 |
| 页面关键字 | 页面关键字 | 3–6 个相关短语，英文逗号分隔；非 Google 排名因素。 |
| 标签 | 标签 | AI 给出栏目建议，人工复核，避免大量同义标签。 |
| 发布时间 | 拟定发布时间（北京时间） | 默认留空，由人工按实际发布时刻填写；不得用 AI 猜测事件发生时间冒充发布时间。 |
| 置顶、推荐、头条 | 三个复选框 | 默认均关闭，只由编辑决定；不会由 AI 设置。 |
| 标题图片（截图要求 1:1 方图） | 标题图片构图建议 | AI 只提供文字建议，没有文件或上传接口；必须由人工使用有授权的图片到网站后台上传。 |
| 关联软件 ID | 整数输入 | 默认 0；只有人工确认了对应软件后才填入真实 ID，AI 生成始终强制 0。 |
| 内容简介（必填） | 内容简介 | AI 给出独立、准确的文章摘要；是否作为 HTML `meta description` 输出取决于目标网站模板。 |
| 新闻正文（必填） | Markdown 编辑/预览、“复制新闻正文” | 剪贴板含格式化 HTML 和纯文本，仅保留参考来源；**不重复复制主标题**，因为 CMS 有独立标题字段。人工粘贴后要核对编辑器清洗格式。该工具不在正文中附加 AI 生成声明；公开发布前请按适用规定另行确认内容标识要求。 |

### SEO 原则与边界

- 标题具体、简洁、与正文一致，避免夸张、复写相同关键词。Google 标题显示没有固定字符数限制，可能根据设备截断或改写；[百度搜索网页标题规范](https://ziyuan.baidu.com/college/articleinfo?id=2728)同样要求准确、简明、避免堆砌。
- 内容简介描述当前页面而非套模板；Google 搜索摘要主要从页面正文产生，也可能采用 `meta description`，不保证展示本字段。
- Google 不将 `meta keywords` 作为索引或排名信号；截图的“页面关键字”仍可为该 CMS 或其他用途填写，不能宣称会提高 Google 排名。
- 可信的来源、实际报道事实、人工审校比追求固定字数或机械堆词重要。网站版与公众号版提示词分开，不因 SEO 凭空增加功能、价格、数据或软件关联。
- 真正的 `NewsArticle` 结构化数据、日期、可索引图片、规范网址与 sitemap 应由**正式网站模板**提供，而不是粘贴到 CMS 正文；编辑稿无法保证搜索收录、排名或富结果。

参考：Google Search Central 的 [标题链接建议](https://developers.google.com/search/docs/appearance/title-link)、[搜索摘要建议](https://developers.google.com/search/docs/appearance/snippet)、[meta 标签（明确忽略 meta keywords）](https://developers.google.com/search/docs/crawling-indexing/special-tags)、[以读者为先的内容](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)、[文章结构化数据](https://developers.google.com/search/docs/appearance/structured-data/article)。

## 历史草稿清理

当前版本的提示词、生成落库、人工保存、预览和复制均不再附加 AI 生成声明，参考来源仍保留。旧稿详情也会过滤历史自动声明；以下脚本可显式清理数据库中的旧声明，无需调用模型或重生成正文：

```bash
docker compose exec -T backend python scripts/remove_draft_ai_disclosures.py          # 只预览
docker compose exec -T backend python scripts/remove_draft_ai_disclosures.py --apply  # 确认备份后写入
```

脚本仅处理网站和公众号草稿，保留原正文及参考来源，跳过正在生成或仍由生成任务持锁的草稿，每篇修改增加修订版本，重复执行不会再次改动。迁移后请刷新已经打开的草稿页面，避免使用旧修订版本保存。

2026-10-11 本机验收：清理 2 篇网站稿、3 篇公众号稿，包括正文中无 Markdown 标题的旧声明；通过还原被删行后的内容哈希，确认正文与来源没有其他改动。后端 464 项通过、25 项因环境条件跳过；前端 103 项通过，构建与静态检查通过；已更新前后端和相关任务容器，9 个服务均健康。清理只涉及草稿库，不会修改已人工发布到外部 CMS 的内容。

## 技术边界与验证

网站稿通过 `channel=site` 与旧 `wechat` 草稿隔离：独立路由、读写 API、生成提示词、任务和审计动作，复用表的版本锁及材料快照。启动时为旧库幂等补列并建板块索引，旧行默认公众号。队列恢复按 `channel` 选择对应任务；两个板块共用成本额度锁以避免并发超限。编辑、重生成、删除均携带修订版本防覆盖。

验收：前端 84 项通过；后端离线 410 项通过、25 项按环境跳过；另外以独立 PostgreSQL 测试库和随机 schema 运行 9 项真实数据库迁移/锁/额度并发测试，全部通过，测试库随后删除。已更新本机 Docker Compose 的 backend、worker、ai-worker、beat、nginx，9 个服务 healthy；旧草稿仍为公众号 3 篇，网站稿初始为 0 篇，数据库新增 9 列均存在；本机入口健康接口 200、未登录网站稿/公众号稿接口均 401，网站生文任务在 ai-worker 注册且路由 ai 队列。未登录浏览器访问网站稿路由会正常跳转登录页。没有调用真实供应商模型，没有自动向网站发布，也没有直接处理目标 CMS 的登录或图片上传。

网站稿任务只消费隔离测试中假模型或正式配置的模型；无素材会失败而不调用模型。本板块目前没有 CMS 自动发布/图片上传或真实搜索引擎收录测试。
